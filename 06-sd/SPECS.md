Это репозиторий с решениями заданий по курсу "Встраиваемые системы" для младшекурсников Физтеха.

Программируем встраиваемое программное обеспечение (прошивки) на платах Raspberry Pi Pico.

Все шаблоны проектирования прошивок очень важны. В них заложены очень важные принципы лаконичного, понятного кода и, как следствие, рабочего кода.

Задача:
- сделать в папке "06-sd" проект ещё одной прошивки под Pico, который читает данные с АЦП и записывает их в WAV-файл на SD карту так, чтобы эти файлы потом можно было скачать, подключив карту к компьютеру

Имеется из железа:
- Raspberry Pi Pico
- microSD card reader (на фотографии)
- microSD карта (на фотографии)
- провода, чтобы их соединить

Есть примеры решённых заданий (в скобках то, что нужно отттуда взять):
- blink (лаконичный минималистичный код)
- control (работа с сущностью api, init и handler отдельных сервисов)
- echo (работа через switch case)
- printf (красиво структурированный вывод, чёткое понимание памяти и адресации)
- adc (работа с АЦП, работа с API)
- bme (драйвер внешней микросхемы в виде библиотеки и проброс его API до пользователя через Python и COM-порт)
- dysplay (работа с внешней микросхемой)

Реализовать проект нжуно строго в три этапа. Переходить к следующему будем после моего подтверждения, что предыдущий готов.

Этапы:

- В первую очередь проверить аппаратную работу с SD картой, то есть на низком уровне записать в неё шаблон буфера, потом прочитать его и убедиться, что ванные совпадают. Нужно, чтобы этот низкоуровневый тест всегда можно было запустить через текстовый интерфейс, даже полсе реализации второго этапа.

- Когда станет понятно, что запись и чтение во флеш работает, нужно реализовать запись файлов. Можно начать с  WAV файлов с синусоидальным сигналом на частоте, которую можно услышать. По команде из терминала, содержащей частоту и секунды прошивка должна сгененрировать и записать на карту файл заданной продолжительностью с аудио-сигналом нужной частоты.

- На третьем этапе нужно записать в WAV файл занчения, которые оцифрует с GPIO-порта встроенный АЦП. Для тестов я подам на этот порт внешнее напряжение синусоидальной формы. Потом послушаю получившийся файл на компьютере.

Требования:
- Учти физические особенности работы с SD-картами, если это FLASH память. Можно ли там писать по байтам или только страницаим? Можно ли там переписывать по верх записанных данных или нужно для начала стереть сектор? Или это всё решается на SD-картах аппаратно за SPI? Напиши о работе с SD-картой в этом контексте заметку "06-sd/SD карты и микроконтроллерами.md". Дополняй эту заметку гарблями и полезными советами по ходу разработки, чтобы человек потом смног легко понять, как это повторить.
- Единый API, который будет только дополняться по ходу продвжения, но не будет уменьшаться. Чтобы всегда была возможноть низкоуровненовй проверки.
- Нужны команда начала записи и остановки записи.
- Нумерация WAV-файлов последовательная. Если флешка чистая, то начинаем с единицы.
- Проверку устройства буду делать и через терминал и через Python-скрипт, о котором будет в следующей пункте.
- По ходу продвижения нужно развивать Python скрипт, который упрощает пользовательские сценарии взаимодействие с API, когда нужно выполнить несколько команд подряд, например, записать строго 3 секуны. В скрипте и API нужно реализовать возмоность узнать, какие на карте сейчас есть файлы и возможность скачать выбранный файл и возможность скачать все файлы. Сохранять файлы нужно в папку с датой и временем начала скачивания с оригинальными называниями.
